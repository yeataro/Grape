# S05 function-mode batch contracts

This is an implementation submission for independent review, not acceptance or completion of S05. IH-005 and accepted DEC-GRAPE-003 / AC-GRAPE-002 define the behavior; frozen contracts and old exact modules are unchanged.

- New exact owner grape.resources.function-networks 0.1.0 supplies definition codec2 with mandatory emissionMode expand/function and array-extent codec2. It explicitly upgrades the old exact network/extent owners. New definitions start expand. Existing old documents keep their pins and data until the Application command creates an explicit upgraded load. Missing/unknown new mode never means expand; missing exact owner remains opaque and blocks generation. Old owner files and fingerprints remain unchanged.
- ResourceDefinition.networkEmission, upgrades and extentInputs are owner contracts. The Application inventories exact registered owner upgrades, validates a detached candidate and publishes a new session under stale/load guards. Graph owns mode mutations, localization, shared-reference changes, typed loss and History; Canvas only submits the public revision-scoped command. Definitions' pure constant analysis uses node-owned emission semantics, bounded symbolic expressions and no GLSL parsing/evaluation. All authored nodes and unused dependent definitions participate. Function ordinary parameters/results are runtime; fixed shape facts remain node-owned.
- Enabling an ineligible function rejects before localization/detach/history. An eligible change compares semantically valid before/after constant receiver facts; only newly invalid incoming edges are removed. Pre-existing malformed evidence is retained. One transaction publishes mode/localization/references/losses. Loss payload contains the removed edge and reason; supplementary provenance is namespaced grape.function-mode. Undo/Redo restores the whole document. Expand does not reconnect. Required-input errors remain saveable and prevent generation.
- The compiler deduplicates helper bodies per immutable compile/stage/resource, emits dependencies first and caches each caller evaluation within its frame. Ordinary input and out arguments preserve distinct caller values. Effects are rooted through generic nested calls even when outputs are unconsumed; duplicate live depth writers reject. Helpers do not imply caller-result sharing. No global artifact cache was added. Shared diagnostics carry definition/internal-node subjects and related call sites.
- New grape.nodes.function-operations 0.1.0 owns the small constant-input/Add/shape-length/Source/vertex-position/pixel-effect mechanisms and es300-functions profile needed for this batch. They do not claim equivalence to all legacy catalog nodes. Uniform bindingSchema uses source resource IDs and default values without runtime leases. Actual tests qualify float Uniform, fixed float array, nominal field, pixel effects and separate vertex/pixel helpers. No sampler/native TOP/TD, arrays-of-arrays profile, specialization or full catalog claim.
- Personal canonical serialization/admission are unchanged. SHA256 now uses exact @noble/hashes2.0.1 (sha2.js) from the npm lock, through the application digest provider; this standard pure dependency works without crypto.subtle. Browser identity uses injected crypto.getRandomValues, sets UUIDv4 bits and fails closed if unavailable. No Math.random, weaker digest, browser setting, TLS bypass or native dependency was added.
- apps/web/main.ts composes the new exact modules/profile and browser identity provider; ownership.json registers the five new files and public exports/external dependency honestly. Enforcement code is unchanged except registering new exact module pin checks. The deployment helper is a separately hashed Coordinator input, outside product code. It serves preverified archive bytes and shows exact identity without secure-context crypto.

Known-vector tests compare empty/abc/Unicode/one-million-a SHA256 to a separate Node oracle; prior Personal regressions verify existing canonical checksums. Three actual served HTTP origins exercise product operations from one machine. They do not prove second-device access. The locked package's engines and provenance are in package-lock.json; upstream primary source: https://github.com/paulmillr/noble-hashes/tree/2.0.1 . No package audit remediation outside scope was performed.
