## Mouse pan

**Source trigger and ownership.** The canvas has `tabIndex=0`. Touch is intercepted by the dedicated capture handlers; the ordinary canvas `onpointerdown` branch handles other pointer devices. For a primary-button drag, the target must not be inside `.node`, `path,.link-direction`, or `.graph-navigation`. The graph-focus helper receives focus, closes Creator, and clears native text selection. Left drag pans unless Box Select mode is on or Shift is held. Right drag is marquee selection. Ctrl/Meta are additive-selection inputs and do not themselves turn an ordinary left drag into marquee. Alt has no special pan mapping in this handler. Canvas view controls stop pointer propagation, avoiding an accidental pan. (`src/editor/graph_ui.js:2388-2414`; `src/editor/app.js:1475-1480`; `src/editor/graph_ui.js:1293-1298`.)

**Intermediate state.** Pointer capture is requested. Initial pan and pointer are remembered. On every pointer move, pan target is `initialPan + (currentClient - initialClient)/uiScaleFactor()`. A `>3` client-pixel movement flag controls click-versus-drag outcomes; it is recalculated on each move, not latched, and does not gate the pan update itself. Pan goes through the shared damping setting. Scale defaults to the displayed `scale` when `moveCanvas` is called. (`src/editor/graph_ui.js:2409-2415`; `src/editor/app.js:556`.)

**Finish/cancel.** Pointer up clears the move/up handlers and marquee; it does not re-sample its final coordinate. An ordinary moved pan preserves selection. If the current movement flag is false and the original button was left, release either completes an armed wire onto blank space or clears selection. Pointer cancel clears the move/up handlers and hides marquee. It does not restore the starting view, finish a motion target, or explicitly release capture in this code. Escape freezes an active animation through the shared damping listener, but no Escape handler cancels the ordinary mouse-pan owner; later pointer movement can continue panning. (`src/editor/graph_ui.js:2416-2420`; `src/editor/app.js:576`.)

**Uncertain/limits.** This handler does not contain the Dolly-specific lost-capture, blur, resize, graph-context identity, or button-still-held checks. Do not promise rollback, full lifecycle cancellation, or selection preservation for a drag returning within 3px of its start. The source has a broad canvas handler rather than Dolly's exact background-element allowlist. Overlay-specific propagation may further limit eligible targets.

**Test intent.** `tests/browser/test_canvas_dolly.cjs:44-46` expects left drag +30/+20 CSS px with damping off and no graph/history changes. `tests/browser/test_canvas_damping.cjs:44-48` expects a mouse pan to ease to its final displacement without replacing node/wire DOM, graph/history mutations, or API POSTs. `tests/browser/test_canvas_motion_input.cjs:17-35` replays 20 frames with input 2 ms after each RAF timestamp and expects visible movement by frame 2, one pending callback, and exact final displacement.

## Wheel zoom and zoom preset menu

**Source wheel trigger.** Every wheel event reaching `#canvas` is prevented, registered with `{passive:false}`. There is no modifier check, `deltaMode` conversion, horizontal `deltaX` use, wheel threshold, or dedicated graph-null guard in that handler. Specific embedded controls such as node preview/code boxes and selection-toolbar controls stop wheel propagation. (`src/editor/app.js:1570,1657`; `src/editor/inspector.js:917`; `src/editor/selection_ui.js:443`.)

**Anchored math.** Desired scale is `previousScale * exp(-deltaY*.001)`; negative delta zooms in. Anchor is `(client - canvasRectOrigin)/uiScaleFactor()`. `previousScale` and pan use a pending **canvasDamping** target when one exists, otherwise the displayed view. Clamp to the current minimum and 1.7. For each axis, `nextPan = anchor - (anchor-originPan)*nextScale/previousScale`. This is why fast wheel input accumulates and the anchor remains fixed while interpolation progresses. A pending Frame/Center transition is superseded using its displayed state rather than its hidden destination. (`src/editor/app.js:1420-1422,1570`; `src/editor/app.js:556-566`.)

**Finish/cancel.** Each wheel event supplies a new target; animation completes after the last input. There is no separate wheel release/commit event or rollback. Escape/new canvas pointer interaction freezes displayed state; blur, resize, or hidden document completes the pending target once. These lifecycle rules come from shared damping, not the wheel handler. (`src/editor/app.js:538-576`.)

**Source presets.** Click/tap the percentage button to open a native popover above it. Its rounded percentage reflects displayed zoom; the menu checks a preset only when actual scale matches within `.000001`. Presets are `[20,25,50,75,100,125,150,170]`; 20 is hidden when overview is off. Selecting a preset calls `setGraphZoom(percent/100)`, anchored at the **canvas center**, using pan/zoom damping, then closes and returns focus to the opener. `setGraphZoom` ignores missing graph or non-finite values. (`src/editor/app.js:1407-1435`.)

**Preset keyboard/focus.** Click-opening focuses the nearest visible preset on the next RAF. Arrow Up on the opener opens and focuses the last visible preset; Arrow Down chooses the first. In the menu, Up/Down wrap; Home/End jump to first/last visible item. Escape prevents default, closes, returns opener focus; Tab closes and focuses the opener while allowing normal Tab default handling. Menu keydown stops propagation, preventing H/F or graph commands. Menu placement is clamped to the viewport and recomputed on resize. Native popover behavior handles outside dismissal. (`src/editor/app.js:1426-1451`; `src/editor/index.html:57`.)

**Test intent.** `tests/browser/test_canvas_zoom_menu.cjs:22-66` asserts open/cancel view invariance, seven ordinary presets and center anchoring, keyboard/touch access, graph-focus compatibility, UI scale/narrow placement, and wheel endpoints. Its assertions use immediate or two-RAF settling in several places, which is not a reliable guarantee of completion with current default-on damping. `tests/browser/test_low_zoom_overview.cjs:82-94` explicitly covers 20% wheel/Dolly/menu/fit/pinch when overview is on. `tests/browser/test_canvas_damping.cjs:34-42` asserts two wheel deltas accumulate into one RAF loop and preserve intermediate graph coordinates.

## Middle-mouse Dolly

**Source trigger and preconditions.** Middle button (`button===1`) directly on an element whose ID is `canvas`, `world`, `cards`, `wires`, or `groupframes`. No modifiers required or rejected. It cannot begin without a graph or while canvas pointer-move ownership, wire gesture, armed link, node placement, touch graph gesture, node drag, or node resize is active. A second pointerdown while `canvas-dolly` is active is prevented. Node/wire/group-frame content/control surfaces are not admitted by that ID allowlist. Numeric fields retain their own Value Ladder path. (`src/editor/graph_ui.js:2352-2354,2400-2406`.)

**Begin/feedback.** Prevent default, stop any existing motion at displayed coordinates, close Creator, focus canvas. Snapshot graph owner, current data, stage, UI scale, pan/scale and pointer anchor. Add `.canvas-dolly` (zoom-in cursor), capture pointer. Anchor stays at its starting local canvas coordinate. Cursor changes to zoom-out for negative movement and back to zoom-in for positive movement; zero delta retains prior direction. (`src/editor/graph_ui.js:2354-2358,2371-2376`; `src/editor/style.css:197-198`.)

**Intermediate state.** For each event of the owning pointer: `delta=(currentX-lastX-(currentY-lastY))/startUiScale`. Desired scale updates incrementally as `clamp(targetScale*exp(delta*.006), minZoom, 1.7)`. Right/up zoom in; left/down zoom out; diagonal movements combine algebraically. Because the clamped target and latest pointer are retained on every event, reversing at a bound responds immediately. Zoom uses the shared anchored zoom/damping path. (`src/editor/graph_ui.js:2368-2374`.)

**Finish.** Owning-pointer middle-button up performs one final update and finishes. A move missing bit 4 in `buttons` also finishes. Any wheel event observed by the window capture listener finishes Dolly before normal wheel handling. Successful finish removes handlers/classes/listeners, releases capture, and calls `stopCanvasMotion(true)` while context is still valid: the pending target is reached immediately, so Dolly does not leave a post-release smoothing tail. No graph/selection/history transaction is created. (`src/editor/graph_ui.js:2360-2381`.)

**Cancel/invalid context.** Escape is prevented and stops immediate propagation; pointer cancel, lost pointer capture, blur, resize, or hidden document invokes `finish(true)`. Starting pan/scale is restored immediately only if graph object, current data, stage, and UI scale still match the start snapshot. An invalid-context move finishes without restoring old coordinates or completing an old target. Thus a UI-scale change can invalidate rollback rather than place old units into the new layout. (`src/editor/graph_ui.js:2359-2383`.)

**Test intent.** `tests/browser/test_canvas_dolly.cjs:11-25` covers horizontal/vertical/diagonal movement, anchor and direction cursors across 80/100/125% UI scales. Lines 26-33 cover normal 25–170% limits, reversal, Escape/blur rollback and middle-click selection preservation. Lines 34-43 cover excluded surfaces, Value Ladder, readonly and damping. Overview-on 20% is separately asserted by `tests/browser/test_low_zoom_overview.cjs:85-94`. Source covers additional cancellation paths that these Dolly tests do not explicitly exercise.

## Home, Frame and Center

**Home sources.** Unmodified H, `#fit` button, or context menu `fitAll` all call `fit()`, which fits every node in the current graph/stage/subgraph immediately. It does not clear/change selection. The immediate path cancels any active transition without first jumping to that transition's hidden target. (`src/editor/graph_ui.js:2461-2467,2904`; `src/editor/app.js:843-855,1565,558`.)

**Frame sources.** Unmodified F, the selection toolbar Frame action, or context menu `fit` calls `fitSelection()`. Selected nodes are used only when `selectedEdge===null`; otherwise, or when there are no selected nodes, all current nodes are used. Frame always requests the independent `frameDamping` setting even for its all-nodes fallback. With current defaults it animates for 333 ms; with that setting off it is immediate. (`src/editor/selection_ui.js:91-92,429`; `src/editor/graph_ui.js:2464,2905`; `src/editor/app.js:843-847`.)

**Bounds/destination.** Empty node arrays return without a view change. Bounds include node DOM `offsetWidth/Height`; fallback width is positive authored width or 190, fallback height 180, with position defaults 0. Fully included group frames contribute their bounds; their padding is 24 and title extension 28 world units. Fit scale is `max(minZoom, min(1,(canvas.clientWidth-100)/boundsWidth,(canvas.clientHeight-140)/boundsHeight))`, centered in the canvas. Fit never zooms beyond 100%. The lower zoom clamp means very large graphs or very small viewports need not wholly fit on screen. (`src/editor/app.js:827-847`; `src/editor/frames_ui.js:2,12-21`.)

**Keyboard guards.** H/F run only when command scope is body, root, or graph workspace and there is no prevented event, IME composition, contenteditable, ordinary input/select/textarea, dialog/menu/popover, library/details/Creator/shader-selector target, floating-panel target, canvas pointer gesture, Value Ladder/pending Ladder/preset menu, armed link, wire/node drag/node resize/touch gesture. Ctrl, Meta, Alt, and Shift versions of H/F are excluded. Readonly is not a blocker. Repeated H/F are not ignored; repeated Frame with the identical target is a no-op and does not restart its motion clock. `graphCommandReady` does **not** explicitly exclude `nodePlacement`, unlike some other commands; do not infer that additional guarantee solely from the general wording. (`src/editor/graph_ui.js:2432-2467`; `src/editor/app.js:562`.)

**Animation interruption.** Home supersedes motion immediately. Frame target changes retarget shared motion; Escape/new graph pointer freezes displayed state. Blur/resize/backgrounding completes the target. Empty graphs return before any stop call in `fitNodes`; hence an empty-graph Home is not source-guaranteed to cancel an already pending motion. (`src/editor/app.js:538-576,843-847`.)

**Related Center/automatic navigation.** `centerNodes()` preserves current zoom and only pans, returns for empty nodes, and uses a forced animation with default 333 ms when requested. Arrow-view preference can keep the view, force animated Frame using the configured Frame duration, use instant Frame, animated Center, or instant Center. Forced animation is independent of the general Frame checkbox. Default arrow view is `none`. Initial load, stage switching and subgraph entry/exit call instant `fit()`. Diagnostic navigation stops motion and centers the target at a displayed scale clamped to `.7–1`. (`src/editor/app.js:838-855,202-207,873,1564`; `src/editor/functions_ui.js:42,47`; `src/editor/graph_ui.js:2`.)

**Test intent.** `tests/browser/test_canvas_framing.cjs:20-27` asserts current defaults on/150/on/333 and selected/multi/unselected framing readonly. Lines 29-45 assert field/IME/modifier/gesture guards. Lines 48-67 assert all four toggle combinations, 200/450 ms independence, and identical F not restarting. Lines 69-91 assert Home key/button/menu interrupts active Frame with no queued callback, immediate commands cancel pending motion, and graph/history/node DOM remain unchanged. `tests/browser/test_navigation_view.cjs:33-36` covers instant Frame despite enabled general damping and animated Center cancellation.

## Canvas keyboard focus and Focus graph mode

These are distinct states. `focusGraphCanvas()` leaves Viewer inspector mode, schedules inspector refresh if necessary, focuses `#canvas` without scrolling, and removes native text selection. This helper is called on blank pointerdown, Dolly begin, first owned touch and several selection actions. Canvas focus itself has no outline in current CSS. (`src/editor/graph_ui.js:1293-1298,2354,2409,2643`; `src/editor/style.css:196`.)

**Focus graph trigger.** Click/tap `#graphfocus`, use context-menu focus (a proxy to that button), or use exactly Ctrl+Enter or Meta+Enter with no Alt/Shift and without both Ctrl+Meta. Keyboard requires `graphCommandReady`, excludes node placement, and ignores repeats. It then returns keyboard focus to canvas. The button toggles mode directly. (`src/editor/app.js:1469-1479`; `src/editor/graph_ui.js:2432-2443`; `src/editor/shortcuts_ui.js:28`.)

**Visible state.** Toggle in-memory `graphFocused` and body `.graph-focused`; hide top header, location bar, footer and main siblings of graph workspace. Keep graph toolbar/canvas. Move fullscreen button next to focus button; restore it to footer preferences when leaving. Label becomes Restore layout and `aria-pressed=true`. `setGraphFocus` requests a wire refresh, not graph rebuilding, fitting, or pan/scale rewriting. There is no explicit focus animation or storage call. (`src/editor/app.js:1454-1479`; `src/editor/style.css:1722-1731`.)

**Exit/cancel.** Toggle again via the button, context-menu action or Ctrl/Meta+Enter. **Escape does not exit Focus graph.** It can cancel a gesture, close Creator/connection or stop camera motion through their respective handlers, while `graphFocused` stays true. Home/Frame also do not exit Focus graph. This is explicit test intent, not merely an absence inferred from CSS. (`src/editor/graph_ui.js:2480-2482`; `src/editor/app.js:576`; `tests/browser/test_fullscreen_shortcut.cjs:48-64`.)

**Browser fullscreen is separate.** Alt+Enter also works while editing, excludes IME/repeat/other modifiers, and uses the fullscreen API. Unsupported entry disables its button; denied requests display a failure status. Focus graph and fullscreen can be combined independently. (`src/editor/app.js:1461-1466,1481-1495`; `tests/browser/test_fullscreen_shortcut.cjs:45-64`.)

## Shared damping, state transitions, and persistence

| Event | Source-backed transition | Evidence |
|---|---|---|
| Damping disabled or explicit instant operation | Stop pending motion at displayed state, apply new pan/scale and transform immediately; no new target/RAF. | `src/editor/app.js:556-558` |
| First animated target | `lastTime=performance.now()`, `end=now+duration`; schedule at most one RAF. | `src/editor/app.js:561-566` |
| Retarget same motion kind | Set new target and end time, retain `lastTime`; identical target returns unchanged. | `src/editor/app.js:560-566` |
| Different motion kind | Stop existing motion at displayed state, start new one. | `src/editor/app.js:560` |
| RAF | `progress=clamp((now-lastTime)/(end-lastTime),0,1)`; cubic ease-out amount `1-(1-progress)^3`; interpolate displayed pan/scale toward target, advance lastTime; exact final values at 1 and stop. | `src/editor/app.js:544-554` |
| New canvas pointerdown | Freeze displayed view; exceptions include toolbar, canvas-view-tools, selection-toolbar, connection notice and floating parameters. | `src/editor/app.js:571-573` |

| Blur, resize, hidden document | Complete pending target once and cancel callback. | `src/editor/app.js:574-575` |
| Change either damping toggle/duration or arrow-view option | `applyCanvasDamping()` completes old target once, aborts old listeners, installs listeners if still needed. | `src/editor/app.js:568-577,1197,1205` |

Settings live in `localStorage.sgrapeExperimentsV1`, read during installation, parsed over defaults and written when changed. Each enabled flag and duration is independent; stored booleans/durations survive defaults changing. Numeric durations are finite numbers, rounded/clamped 10–1000; controls are disabled while their corresponding toggle is off but retain the number. Checkbox edits apply immediately. ## Touch navigation and gesture transfer

**Eligibility.** Capture listeners accept `pointerType==='touch'`, a loaded graph and a target outside the touch `editable()` exclusions: inputs, textareas, selects, contenteditable, links, non-port buttons, graph navigation, inline values, comment preview, group frame title, connection notice, wire quick actions and floating workspace panels. A first owned touch clears the wire gesture, closes Creator/menu, focuses canvas, snapshots its context and sets pending mode. Each pointer is captured. Long-press delay is 550 ms except on a port, movement slop is 8 client px, double-tap time is 320 ms and distance must be <24 client px. (`src/editor/graph_ui.js:2535-2543,2630-2653`.)

**One-finger pan.** Once movement reaches `>=8px`, cancel the hold timer. On non-node/background touch, choose Box Select if that mode is on, otherwise pan; a readonly node drag is blocked rather than becoming background pan. Pan uses baseline pan plus client delta/UI scale. With damping, baseline target scale is retained. Pointer moves coalesce paint into a RAF; pointer up flushes pending paint before finishing. Final ordinary pan release makes no graph/history edit and cannot trigger a tap once moved. (`src/editor/graph_ui.js:2583-2592,2607-2620,2657-2672`.)

**Two-finger pinch/translate.** When count reaches two, cancel pending touch editing preview, timer and paint; mark moved/hadPinch, clear previous tap and connection, close menu, and rebase. Sample midpoint and distance of the first two tracked pointers. Scale is `clamp(originScale*currentDistance/max(1,originDistance), minZoom,1.7)`. Pan puts the original graph point under the current midpoint (two-finger translation and anchored scaling). Rebase uses a pending motion target when present, otherwise displayed graph coordinates; this preserves the intended destination when lifting one finger during damping. (`src/editor/graph_ui.js:2543-2549,2552-2557,2578-2589`.)

**Finger release.** With other pointers remaining, remove the lifted pointer, release its capture, choose pinch for 2+ or pan for 1, and rebase. Last release finishes ownership. `hadPinch` prevents tap/Creator/connection actions, even if the surviving finger did not move. Camera smoothing may continue after release; unlike Dolly finish, touch `finish()` does not snap the camera to its target. (`src/editor/graph_ui.js:2559-2567,2657-2674`.)

**Cancellation.** Pointer cancel, capture loss, Escape, blur, resize, hidden document, non-touch pointer takeover, touch outside canvas, or card rerender cancels the touch owner and restores unfinished edit previews. The touch cancel function itself does **not** restore starting camera pan/zoom or call `stopCanvasMotion`. Shared Escape freezes displayed motion; shared blur/resize/hidden handlers complete pending motion. Thus “cancels touch editing” must not be restated as “rolls camera navigation back.” (`src/editor/graph_ui.js:2552-2567,2674-2684,1794`; `src/editor/app.js:573-576`.)

**Native event suppression.** Cancelable touchstart/move on non-editable canvas targets are prevented. Trusted synthesized click/double-click/context-menu events are suppressed while points are owned, for touch pointer type, or within 900 ms of the last touch while the last device remains touch. Mouse takeover clears that suppression. The canvas has `touch-action:none`; outside canvas browser navigation is a separate route. (`src/editor/graph_ui.js:2675-2684`; `src/editor/style.css:88`.)

**Test intent only.** `tests/browser/test_touch_editing.cjs:66-70` expects second-finger rollback of node preview into pinch/pan without graph write or page zoom; lines 103-109 cover long press and movement-before-hold. `tests/browser/test_canvas_damping.cjs:70-75` covers two-finger to one-finger handoff preserving the final damping target. `tests/browser/test_low_zoom_overview.cjs:85-94` covers 20% pinch. `test_touch_editing.cjs:119` and `test_touch_webkit.cjs:44` explicitly limit their scope to desktop automated touch/native taps and do not establish physical iPhone/iPad behavior. No such device behavior was verified here.

## Grid, visual density and overview

**Grid behavior.** Grid is display-only adaptation of the constant 24-unit snap lattice. Double `displayGrid` while `displayGrid*scale<14`; `dataset.gridStep` records the world-unit display step. At normal 100% zoom it is 24; at 50% it is 48; at 25% or overview 20% it is 96 (derived from the source rule, not runtime measurement). Dot radius is `clamp(1.05*scale^.65,.45,1.65)` local CSS px. Background step is `displayGrid*scale`, and its offset is `pan - step/2` on both axes. Snapping remains at 24 world units. These thresholds use graph scale, not UI-scale-adjusted physical pixel distance. (`src/editor/app.js:42-46,581-590`.)

**Other zoom-dependent targets.** Wire ring and glow variables are `3/scale` and `7/scale`; wire hit width is `max(6,6/(scale*uiScaleFactor()))`. These preserve usable visual/interaction widths at distance; no new wire transaction is implied. (`src/editor/app.js:586-588`.)

**Overview toggle.** Stored browser preference defaults off. Enabling changes lower bound to 20% and paints overview only below 30%. The normal node layout boxes and sockets remain: CSS hides details using `visibility`, keeps ports/link-navigation/overview label visible, uses category background, and exempts Router/annotation nodes from the ordinary simplification rule. Caption at bottom-left has opacity `.7`; font size is `max(36,10/(scale*uiScaleFactor()))`, retaining at least 10 screen px. Collapsed captions use a 2px bottom inset; ordinary captions use 12px. Overview-body dragging is allowed even with ordinary header-only drag preference. (`src/editor/graph_ui.js:2,94,1688-1694`; `src/editor/style.css:2251-2260`.)

**Turning overview off.** Immediately stop pending motion. If displayed zoom is below .25, restore .25 around the canvas center using an instant move; otherwise just repaint normal mode. An outstanding lower target is discarded. No graph/selection/history changes or view Undo are made. Preference change is stored by the experiment path; failed storage leaves only page-local effect. (`src/editor/app.js:1191-1213`.)

**UI density remains separate.** Standard/Comfortable size setting is not graph zoom. It sets root `data-ui-size`, shares a single 75–125% whole-page scale, and preserves the graph scale variable. Size/scale changes dispatch resize and request wire refresh; because resize is a gesture lifecycle event, it can finish/cancel active navigation as described above. `docs/ui/WORKSPACE_LAYOUT.md:104-108` describes Comfortable chrome growth and native browser zoom independence. Current source parsing/persistence is in `src/editor/app.js:1314-1377`. Tests intended to cover shared density/scale and unchanged graph state include `tests/browser/test_ui_scale.cjs:66-89`.

**Test intent.** `tests/browser/test_low_zoom_overview.cjs:22-43` covers default 25%, strict threshold, stable card/socket/draft geometry, 10px text at 75/100/125 UI scale and Router/note form. Lines 82-116 cover center-preserving disable, every zoom path to 20%, focused numeric drafts, animation threshold crossing and stored default-off Reset. A search found no dedicated current test assertion for `gridStep`, `grid-dot`, or the `displayGrid` threshold itself; grid formulas here are source-backed only.

3. **“Both off means zero listeners” has an exception.** Animated arrow Frame/Center modes force animation and retain/install motion listeners even with the two general toggles off (`app.js:559,570`). Older prose in `WORKSPACE_LAYOUT.md:62` does not state that exception.
4. **Cancellation is not one universal rollback.** Dolly restores its starting view under valid context. Ordinary pan does not implement that rollback. Touch cancel restores edit previews, not camera origin. Generic Escape freezes camera, while generic blur/resize/background completes its pending target. Do not reuse one cancellation sentence for all four mechanisms.
5. **Escape retains Focus graph.** Current explicit test assertions in `test_fullscreen_shortcut.cjs:49-64` match source. Returning to layout requires toggling focus again. Browser fullscreen remains independent.
6. **Animated operations are asynchronous.** Preset/wheel outcomes should be reviewed after `canvasMotion===null` rather than inferred from a fixed two-RAF settle. `docs/development/STATUS.md:203` historically acknowledges an original-HEAD zoom-menu upper-bound assertion failing because its wait did not cover damping completion; that report is not a new run here.
